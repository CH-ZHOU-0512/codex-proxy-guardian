# Codex Proxy Guardian v1.4.2

这是一个 Windows 稳定性热修复，解决同一代理端口在 HTTP 与 SOCKS5 之间被反复识别时，Codex 被连续关闭并重启的问题。

## 问题表现

Clash Verge、Mihomo 等程序常把 HTTP 与 SOCKS5 同时放在同一个混合端口上。旧版本在 HTTP 验证短暂失败时会正确回退到 SOCKS5，但 HTTP 恢复后又会因为系统代理候选分数更高而立刻切回。虽然主机和端口完全没变，两次协议切换仍会分别触发一次 Codex 重启。

## 修复内容

- 同一主机与端口存在多个可用协议时，保留当前已经验证并正在工作的协议，不再为了候选优先级回切。
- 当前协议真实失效时，仍可在防抖后切换到同端点的其他可用协议。
- 代理主机或端口真实变化时，仍按原有安全策略更新并重启 Codex。
- 用户显式指定的 `ProxyOverride` 或 `ExplicitProxy` 始终优先，不会被粘滞策略覆盖。
- 新增三组 Windows PowerShell 5.1 回归测试，覆盖同端点协议抖动、不同端点切换和显式代理覆盖。

本版本不修改 Windows 系统代理、WinHTTP、DNS、路由或永久环境变量。
