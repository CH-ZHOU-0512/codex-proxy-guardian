# Codex Proxy Guardian v1.3.0

这一版补上了代理协议与自动配置的主要兼容缺口：**纯 SOCKS5，以及系统 PAC/WPAD。** Guardian 仍坚持先发起真实请求、再决定是否让 Codex 使用，不会因为看到常见端口就猜协议。

## SOCKS5

- Windows、macOS、Linux 都接受 `socks5://`、`socks5h://` 和常见的 `socks://` 写法，并统一使用代理端远程解析 DNS；
- 未知的常见代理程序监听会先后按 HTTP 与 SOCKS5 验证，只有实际请求成功才确认；
- Windows 使用系统自带 `curl.exe` 做 SOCKS5 请求，macOS/Linux 使用 Go 标准库原生 SOCKS5 传输；
- 桌面应用接收 Chromium 支持的 `socks5://` 启动参数，Linux `codex-guard` 保留 `socks5h://` 环境语义；
- SOCKS4 与嵌入账号密码的代理 URL 继续拒绝。

## PAC / WPAD

- Windows 通过当前用户 WinHTTP 自动代理解析器处理“使用设置脚本”和“自动检测设置”；
- macOS 读取 `scutil --proxy`，Linux 读取 GNOME `gsettings` 的自动配置 URL；
- macOS/Linux 的 PAC JavaScript 执行器限制脚本大小、获取时间、DNS 时间、执行时间和缓存周期；
- 支持 `PROXY`、`HTTP`、`HTTPS`、`SOCKS`、`SOCKS5` 和 `DIRECT` 回退链；
- 针对多个 OpenAI/ChatGPT 验证目标求值，解析出的端点仍必须达到真实请求成功门槛。

PAC 可能为不同目标返回不同代理。Guardian 当前只在至少一个实际端点能达到配置的多目标门槛时接管；否则安全地保持原状，不会把某个只适合单一目标的端点强制应用到整个 Codex 进程。

## 信任边界

系统已经配置的远程代理由 `AllowSystemNonLoopbackProxy` 单独控制，默认开启；任意 `ExplicitProxy`、`ExplicitPAC` 或环境变量返回的远程地址仍需 `AllowNonLoopbackProxy: true`。两者都不会修改操作系统网络配置。

## 验证

- Go 测试覆盖真实 SOCKS5 握手/转发、PAC 规则与常用辅助函数、无限循环中断、旧配置默认值迁移；
- Windows 集成测试通过本地 PAC 服务验证 WinHTTP 实际求值，并在真实本机代理端口完成 SOCKS5 网络请求；
- PowerShell 测试、Go 测试与 `go vet` 通过；macOS Intel/Apple Silicon、Linux x64/ARM64 四目标完成交叉编译。

本项目仍是独立社区工具，不提供代理、订阅或节点，也不修改系统代理、DNS、路由、防火墙或永久环境变量。
