它解决什么

浏览器能联网，不代表 Codex 拿到了同一个代理

Clash、Mihomo、v2rayN、sing-box 等程序重启、切换配置或更新后，本地监听端口可能变化。已经运行的 Codex 仍可能记着旧地址，于是出现 Reconnecting、任务中断或内容加载失败。

03

受控修复

变化经过防抖确认后才处理，并使用冷却、频率限制和熔断避免 Codex 重启循环。

04

不碰系统网络配置

只读取代理候选并管理 Codex 进程，不修改系统代理、WinHTTP、DNS、路由或永久环境变量。

SYSTEM · UNCHANGED

工作方式

发现 → 验证 → 稳定 → 生效

  1. 发现收集本机 HTTP/HTTPS 代理候选
  2. 验证确认端口和真实 HTTPS 连通性
  3. 稳定等待变化稳定，过滤短暂波动
  4. 生效为 Codex 配置代理，必要时受控重启

适合

Windows 11、Microsoft Store/MSIX 版 Codex，以及提供 HTTP 或混合端口的 Clash/Mihomo、v2rayN/Xray、sing-box、Shadowsocks、NekoRay、Hiddify、FlClash 等程序。

暂不自动支持

PAC/WPAD、纯 SOCKS、只有 TUN 而没有 HTTP/混合端口，以及企业策略禁止未签名 PowerShell 脚本的环境。

Windows 11 上 Codex 每次都要重连 5 次才开始思考怎么办？

先确认问题是否来自 Codex 没有使用当前有效的本地 HTTP/HTTPS 代理。如果是，Codex Proxy Guardian 可以持续发现并实际验证代理，在端口稳定变化后让 Codex 使用当前代理，并通过防抖、冷却和熔断避免重启循环。

直接打开 Codex，工具会自动运行吗？

会。安装一次后，Guardian 会立即启动，并在以后登录 Windows 时静默自启。默认自动模式会观察普通方式启动的 Codex，必要时只进行一次受控修复。参见讨论区的完整回答。

这个工具等于代理软件吗？

不是。它不提供代理服务器、订阅或节点。电脑上需要已经存在可用的 HTTP/HTTPS 代理，它负责让 Codex 稳定跟随这个代理。

它会修改 Windows 系统代理吗？

不会。它不会修改 Windows 系统代理、WinHTTP、DNS、路由或永久环境变量，只读取候选代理并为 Codex 进程配置经过验证的代理。

还有问题，去哪里问？

可以在 GitHub Discussions 提问，或在兼容性反馈主题留下运行结果；确定是程序错误时，也可以提交脱敏后的 Issue。
