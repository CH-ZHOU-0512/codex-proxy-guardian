The problem

浏览器能联网，
不代表 Codex 用对了代理。

最常见的卡顿，不是“完全没网”，而是 Codex 仍在用旧端口，或者本地端口存在但上游并不稳定。

端口变了

Codex 还在走旧地址

代理程序重启、切换配置或更新后，本地监听端口可能改变。

假性可用

端口开着，但上游不通

只检查“有没有监听”不够，必须通过真实外部请求验证。

证据不完整

HTTP 能用，流式连接仍重连

系统代理承载了普通请求，不代表 WebSocket 子进程已继承显式代理。

The solution

Guardian 只做三件事。

发现、验证、对齐。每一步都有证据，证据不足就保持原状。

01

找到真正的代理

读取系统代理、PAC/WPAD 和常见代理程序监听，再用真实 HTTPS 请求验证。

Discover + Verify
02

让 Codex 跟上

Windows 同时确认受管启动参数和新进程真实流量；需要修复时先用简洁、可最小化的窗口询问。

Evidence first
03

跟上 Codex 更新

新版本让旧证据失效；重新解析入口、验证流量，并通过已验证代理检查和重试适配更新。

Auto audit
它不会做什么？

不提供代理节点，不切换订阅，不修改系统代理、DNS、路由或防火墙。

FAQ

四个问题，
先说清楚。

查看完整 Wiki ↗
安装后直接用 Codex，它会自动运行吗？

会自动运行。Windows 推荐用 Codex (Managed Proxy) 打开；原图标仍可用，证据不足时会先询问。macOS 照常打开，Linux CLI 用 codex-guard。

会修改网络配置或突然关闭 Codex 吗？

不会修改系统网络配置。Windows 只有点击“重启Codex”才会执行；也可以最小化窗口或选择“60分钟后再提醒我”。

看到“正在重新连接”，就是 Guardian 的问题吗？

先看 StreamingProxyGuaranteed。为 false 时，可能只有 HTTP 走了系统代理；为 true 且日志没有 codex_restart / proxy_changed 时，更可能是代理节点上游断流。

自动更新完成后，我能知道吗？

可以。v1.6.0 会发送一次通知，告诉你从哪个版本更新到了哪个版本，并明确 Codex 无需重启；不会每次开机重复提醒。
