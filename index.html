Why it works

不是“改一次端口”，
而是守住整个连接链路。

系统代理、代理程序与 Codex 的启动环境可能分别处于不同状态。Guardian 重新对齐它们，并为每次动作留下证据。

01

检测正在监听的代理

识别系统当前代理，也可跟踪 Clash、Mihomo、v2rayN、sing-box 等常见程序。端口发生变化时，不需要你重新猜。

Discover 127.0.0.1 :7890
02

确认它真的能访问网络

监听存在不代表代理可用。Guardian 会经过实际 HTTPS 验证和异常重试，避免把一次抖动误判成故障。

Verify 200 OK 3× Retry
03

克制地修复 Codex

防抖、冷却期、频率限制与熔断共同工作；只有当有效代理确实改变或修复证据成立时，才会安全接管。

Repair Safe Restart
04

跟上 Codex 自身更新

发现 Store/MSIX 包版本变化后重新解析入口、审计兼容证据并立即检查 Guardian 适配更新；证据不足时保留 Codex，暂停自动修复。

Common questions

先把最容易困惑的事，
说清楚。

还有特殊环境？可以去 Discussions 提问，也可以提交兼容性反馈。

查看问答与兼容性讨论 ↗
直接用 Codex，Guardian 会自动运行吗？

Windows/macOS 会。安装一次后它随登录静默启动，继续照常打开桌面应用。Linux 后台也会自启，但请用 codex-guard 启动 Codex CLI，后台进程无法改写另一个已启动终端的环境。

查看详细问答 ↗
会不会改坏我的网络配置？

不会。它不修改系统代理、WinHTTP、DNS、路由或永久环境变量；卸载也只删除属于本项目的任务、快捷方式和文件。

Codex 显示“正在重新连接”，是不是 Guardian 的问题？

不能只看这行提示。请对照同一时间的 Guardian 日志：出现 codex_restart 或 proxy_changed 时，Guardian 生命周期操作可能相关；两者都没有，而 Codex 或代理软件记录 TLS EOF、WebSocket reset、10054、请求超时或上游 i/o timeout 时，更可能是当前服务商节点断流。Guardian 不会擅自替你切换订阅节点。

查看重连归因方法 ↗
自动和严格模式怎么选？

绝大多数人保持默认“自动”即可。它会先根据真实流量判断；只有你要求 Codex 启动参数绝对一致时，才需要严格模式。

Codex 更新后，我还要手动重新适配吗？

通常不用。v1.5.0 会重新发现新版入口、审计兼容证据并立即检查正式适配更新；没有新版时继续每日检查。若完全未知的上游改动暂时无法确认，Guardian 会保持 Codex 打开并暂停自动修复，等适配版通过原有校验链自动安装。

为什么 Windows 说安装器无法识别？

项目目前没有商业代码签名证书，新 EXE 可能触发 SmartScreen 提示。只从官方 Release 下载并核对 SHA-256；不确定来源时使用可直接审阅的 ZIP 方案，不要关闭 Windows 安全功能。

支持哪些代理程序？

适用于 Clash、Mihomo、v2rayN、sing-box、NekoRay、Hiddify、FlClash 等程序提供的 HTTP/HTTPS、SOCKS5/SOCKS5H 端口，也支持系统 PAC/WPAD 和手动指定 PAC。仅 TUN、SOCKS4 与带账号密码的代理 URL 暂不支持。
